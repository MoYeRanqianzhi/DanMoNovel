**用户定下的规则（2026-09-27）**
- 书号是一本书唯一的索引，也是查数据的唯一索引；只分配一次，永不改变。
- 书号只是索引，本身不包含任何信息：严禁从书号判断分类或其他属性，要知道分类就查数据。分类、书名、简介、章节都可以改，甚至可以像忒修斯之船那样全部换成截然不同的一本书；只要书号一致，就仍是同一本。
- 16 位十进制数字，以 1 开头。创建时按当时的小说分类分配前四位：第一个分类是 `1001`（第四位的 1 寓意第一个分类），理论上可容纳约一万种分类。
- 后 12 位是分类内的序号。第五位（序号的首位）为 1，避免直接从 0 开始；前一万个书号预留。全平台第一本书的书号是 `1001100000010001`。
- 按分类分配前四位只是创建时的安排：某个分类的书超过 12 位能装下的数量时，可以分配其他开头，不作强制要求。这样分配是为了让书号没有太明显的递增，也能直观看出各分类书的大致数量。
- 每个分类各自从 `…100000010001` 开始编号、各自预留前一万个号（用户同日确认）。
- 书号的简写是 DMBN（仿照 ISBN），展示时写作"DMBN 1001 1000 0001 0001"（用户同日确定）。

**How to apply:**
- 地址、接口、数据库、缓存、本地存储一律用书号标识书，不用拼音或书名（同音书名会撞）。
- 16 位书号超出 JavaScript 的安全整数范围（2^53 − 1，约 9.007×10^15），在前端、JSON 与本地存储里必须当作字符串，不能转成 number，否则会丢精度。Go 里可以用 int64（上限约 9.22×10^18），但接口输出仍用字符串。
- 代码里不写"从书号取分类"之类的函数；分配新书号的函数只在创建书时用一次。
- 预留号段里的号可以给平台自己用（例如品牌书）。
- 展示时四位一组，前面写 DMBN：`DMBN 1001 1000 0001 0001`。封底条码编码完整的 16 位书号：EAN-13 只能装 12 位数据，所以用 Code 128（我的选择），条码下方印 DMBN 与书号；尺寸要克制，约占封底宽度的四分之一（用户嫌更大的版本突兀，见 [[design-direction]]）。
