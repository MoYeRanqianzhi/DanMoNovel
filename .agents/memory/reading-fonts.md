**用户的要求（2026-09-27）**
- 阅读字体不止三种。选择方式改成可滚动的列表，每种字体都有文字预览。
- 非 Web 端（桌面、移动客户端）每种字体配下载按钮。安装包默认不打包字体，因为中文字体太大。
- 允许使用设备上已安装的系统字体。
- 允许导入额外的字体文件。导入的字体只在本地使用，不上传服务器；Web 端也存在浏览器里。

**方案（我的判断，用户尚未逐条确认）**
- 列表分三组：平台字体（精选的开源字体，由平台的字体服务提供）、系统字体、我的字体（导入的）。每行先用这款字体本身写出字体名，再给一行预览。在阅读器里预览读者正在读的那一句，其他地方用固定的示例句。
- Web 端：平台字体用按 unicode-range 切片的网页字体。浏览器只下载屏幕上用到的字所在的分片，并自行缓存，所以不显示下载按钮，只在首次使用时显示加载状态。
- 客户端：显示字体大小与下载按钮，把完整字体文件下载到应用数据目录，离线可用，也可以删除以释放空间。未下载的字体，在线时预览用分片网页字体（只取预览句用到的字），离线时用预先渲染好的预览图。
- 系统字体：不申请权限时，逐个检测各平台常见的内置中文字体是否已安装、能否显示中文（用画布渲染对比），只列出可用的。Chromium 内核的桌面浏览器可以再用 Local Font Access API 读取全部已安装字体，需要用户授权。客户端可以用原生接口枚举。
- 导入字体：接受 TTF、OTF、WOFF、WOFF2。Web 端存进 IndexedDB 并申请持久化存储；客户端存进应用数据目录。字体名从文件的 name 表读出，用户可以改名。用到时才用 FontFace 注册。
- 设置同步只同步"选了哪一款字体"。换到没有这款字体的设备时，回退到默认字体并提示用户。
- 三种来源最终都成为页面可用的字体族，因此同样适用于 Canvas 绘制正文（见 [[content-protection-goal]]）；绘制前要先调用 `document.fonts.load()`。
- 这份列表只决定正文字体，不改界面字体。

**Why:** 一款中文字体动辄数 MB 到数十 MB，全部打包会让安装包体积失控；Web 端的切片加载本来就是按需的，再放下载按钮没有意义。导入的字体只在本机使用、平台不分发，平台也就不必承担这些字体的授权问题。

**How to apply:**
- 平台字库目前只收 SIL OFL 1.1 字体，每一款都记录许可与来源。霞鹜新致宋、新晰黑、铭心宋是 IPA 许可，要先确认子集化与改名的条件；京華老宋体、汇文明朝体的许可不清楚，不收录。
- 任何一种来源都要能优雅退化：离线、用户未授权、浏览器不支持相关接口时，列表依然可用。
- 系统字体检测只在用户主动点击时运行，结果只留在本机。Safari 网页看不到用户自己安装的字体，要在界面上说明。
- Safari 可能清除 7 天内没访问过的站点的 IndexedDB，导入的字体可能随之消失；导入时要提示，并在字体丢失时回退。
- 导入字体合集（TTC）时拆出单款字体再注册。
- 字体许可、字体包、浏览器与 Tauri 能力的出处见 [[font-platform-facts]]，其余平台事实见 [[platform-support-facts]]。

**Evidence:** 用户 2026-09-27 原话："字体选择不止三个，所以形式改成可滚动列表，并且文字有预览，对于非web端还要有下载按钮（不能默认把字体打包进去，太大了），同时允许用户使用自己的系统字体、允许额外上传字体（注意不是上传服务器，而是在本地使用，web端也需要放在浏览器里而非在服务器上）"。

**Recheck when:** 用户调整字体来源或客户端打包策略时；确定客户端界面字体的方案时；相关浏览器接口的支持情况发生变化时。
