用户指出技术框架一直没有定下。耽墨是商业站，需要选用合适的框架，才能做好缓存优化与搜索引擎优化。

原型目前是 Vite + React 的纯前端单页应用：页面在浏览器里渲染，所有页面共用同一个地址。这种形式不利于搜索引擎收录，CDN 也无法缓存页面，不能直接作为正式站点的架构。

**Why:** 用户 2026-09-27 的直接要求。小说站的书籍详情、榜单、分类、作者页需要被搜索引擎收录（国内要兼顾百度）；这些页面访问量大，必须能由 CDN 缓存。

**How to apply:**
- 选框架时逐项检查：服务端渲染与流式输出；按路由设置 HTTP 缓存头；SEO 元数据、结构化数据与站点地图；同一套界面还能构建成 Tauri 客户端使用的静态包；能自托管在国内 CDN 之后。
- 每个页面都要有真实的地址，可以分享、收录和直接打开。原型里"所有页面共用一个地址"的栈式路由只是原型阶段的简化。
- 候选方案与调研结论写在计划里；定下框架后，在本条记录决定与理由。

**Evidence:** 用户 2026-09-27 原话："实际上框架一直没有定下了，这种商业站需要合适的框架，才能有足够的缓存优化、搜索优化等"。

**Recheck when:** 框架定下时（更新本条）；用户调整部署或 SEO 策略时。
