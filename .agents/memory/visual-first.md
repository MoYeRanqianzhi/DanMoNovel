视觉效果是第一位的。技术方案必须保证已经做出来的视觉效果不退步，技术难题要想办法解决，而不是简化掉效果。

2026-09-27 迁移到 React Router 时，我曾打算把原型的页面衔接简化成"旧页面直接卸载、新页面淡入"。原型的做法是：新页面盖在旧页面上淡入，返回时顶层淡出、露出原封不动的上一页，同一本书在两页之间飞行。用户指出，只做淡入淡出、没有之前的页面衔接，反而是一种退步。

**Why:** 耽墨的定位是"UI 极致优美、体验极致舒适"，页面衔接与 3D 书的飞行是它区别于普通阅读站的核心体验（见 [[design-direction]]）。用户已经看过并认可原型的效果，任何降级都会被当成退步。

**How to apply:**
- 做架构、框架、性能方面的改动前，先列出会受影响的视觉效果，并确认新方案能完整保留。保留不了时先想别的实现办法；确实无解，要先向用户说明并征得同意，不能默默降级。
- 迁移或重构之后，要在浏览器里对照原来的效果逐项验收（页面衔接、飞行、开书推进、主题墨晕等）。
- 评估方案时把"视觉效果是否保持"作为第一条标准，工程便利排在后面。

**Evidence:** 用户 2026-09-27 原话："如果只做淡入淡出，而没有之前的页面衔接，反而是一种退步，视觉效果是第一位，剩余的技术难题想办法解决，必须保证视觉效果"。

**Recheck when:** 用户对某个具体效果改变了要求时。
