6. **正文保护**（目标边界见记忆）：
   - Canvas 绘制正文：先用隐藏的测量容器（同样的多栏或竖排排版）逐字取 `Range.getBoundingClientRect` 得到每个字的位置与所在页，然后移除测量容器，把字画到每页的 canvas 上。测量前必须先 `document.fonts.load(字体描述, 本章文字)`，因为字体按需分片加载，而 canvas 不会在字体到达后自动重绘。横排用 alphabetic 基线，y 取字框顶加 `measureText().fontBoundingBoxAscent`；竖排在字框中心居中绘制，标点换成竖排专用字符（U+FE10–FE19、U+FE30–FE44）。设备像素比上限约为 3。滚动模式把各页竖向拼接（分块），避开 Safari 的 canvas 面积上限（约 1670 万像素）。选择、划线、段评气泡都基于逐字位置计算。
   - 加密传输：在前端做一个模拟服务端模块，用 WebCrypto 的 ECDH P-256 协商会话密钥（HKDF 派生），章节以 AES-GCM 加密下发，只在内存中解密。
   - 内置复制：未登录时弹出登录面板（示例账号）；服务端校验单次字数上限、每日配额与频率，返回正文并附出处（可选附加零宽字符指纹，便于追溯）。剪贴板写入：Chrome 在 await 之后调用 `navigator.clipboard.writeText` 可用；Safari 要在手势内同步创建 `ClipboardItem` 并传入 Promise；Tauri 用剪贴板插件。拦截系统的复制、右键菜单与打印。
   - 读屏模式：改为渲染 DOM 文本，作为无障碍兜底；为 AI 听书预留一条同样走鉴权与限速的正文获取通道。
7. **docs/**：见待办。架构文档要写明旧方案的教训：避免为跨端共享 UI 而自建适配层与预览版依赖。

1. **（已完成，验收见第 2 节）迁移到 React Router v8 的 pnpm workspace**（框架已于 2026-09-27 定下，见 [web-framework](../memory/web-framework.md)；原先的"Vite 多入口"方案作废）：仓库根目录建 pnpm workspace。`packages/design` 放令牌与主题样式、theme、book3d、flight、基础组件、fonts、lib；`packages/data` 放示例数据与类型（以后换成调用 Go 接口的客户端）。`apps/novel` 与 `apps/author` 用服务端渲染（作者站也要 SEO），`apps/admin` 用 SPA 模式。开发时三站各占一个端口：5173 小说站、5174 作者站、5175 管理站。所有页面改为真实地址，但**页面衔接必须与原型一致**（用户 2026-09-27 纠正，见 [visual-first](../memory/visual-first.md)）：React Router 只负责地址、数据加载、服务端渲染与缓存头；页面由共享层的"页面栈"自己渲染（从 `useMatches()` 取当前路由的 `handle.Screen` 与 `loaderData`），旧页面在新页面进场时保持挂载，返回时仍在原处，飞行引擎沿用"两端都登记后再测量"的原始做法。浏览器后退与 Android 返回键按历史记录里的页面 id 识别为出栈。主题偏好存本地，`<head>` 里的内联脚本在绘制前写好 `data-theme`（公开页面的 HTML 要能被 CDN 缓存，不能按个人偏好渲染）。启动页只在客户端或首次访问时出现，不挡住搜索引擎与普通访客看到的正文。原 `prototype/` 目录迁移完后删除（用 git mv 保留历史）。

## 4.2 用户追加：章节无感加载（2026-09-27，进行中）

规则与原话见 [seamless-reading](../memory/seamless-reading.md)。阅读器原先每次换章都走 `gotoChapter`，先播 560ms 加载动画再切换；分页只针对当前一章；滚动模式只有单章，要点"下一章"。用户随后补充：多缓存几章、预取后几章，需订阅的章节不能出 bug。

设计（实现中）：
1. **示例接口** `packages/data/src/api.ts`：模拟 300–900ms 网络延迟；前 `FREE_CHAPTERS`（30）章免费；"已订阅"记在本地存储 `danmo:owned`，示例书架上读过的章节视为已订阅；锁住的章节返回 `{ status: 'locked' }`，不抛错。正式版换成请求 Go 接口，签名不变。
2. **章节缓存** `apps/novel/app/reader/chapters.ts`：往后预取 3 章、往前 1 章，遇到锁住的章节就停（绝不因预取而订阅）；进行中的请求去重；"锁住"不进缓存（订阅后会变）；失败记为 error，可重试；最多缓存 12 章，先丢离当前位置最远的。详情页与书架在读者点开之前就预取将要打开的那一章。
3. **分页模式**：页面以（章，页）定位，同时测量前后相邻章节的页数；翻过章末用同样的翻页动画直接进入下一章首页，往回翻停在上一章末页。内容没到时这一页显示加载动画，延迟 220ms 才淡入，数据很快到就不会闪；锁住的章节是一张订阅页，订阅后原地换成正文。
4. **滚动模式**：相邻章节接成一条连续滚动，接近两端时接上前后章（往前接只接已取到的章，免得上方内容高度变化）；最多同时挂 5 章。用锚点（视口顶端所在的章与章内比例）手动补偿滚动位置，因为 Safari 不支持 `overflow-anchor`；读到哪章就更新页眉、进度与地址（只替换地址）。
5. **初次打开**：深链接进入时服务端输出的试读开头一直显示到本章正文取到，不先闪加载动画。

**验收（2026-09-27，Playwright，390×844；4.2 与 4.3 一起）**
- 已验：
  - 书架预取后打开阅读器，没有加载动画。
  - 跨章的翻书、左右平移、上下平移、左右覆盖、上下覆盖，页眉页脚随书页一起动；翻书与覆盖放慢到 1/10 截了中途帧。
  - 反向翻页：点左侧是下一页，书脊在右侧，左方向键是下一页。
  - 滚动模式：往下连续接上下一章；往上接上一章时视口里的文字不动（前后差 1px）；同时最多挂 5 章；地址与页眉随章切换。
  - 订阅页：锁住的章不能往后翻（有提示），订阅后原地换成正文，目录里未解锁的章带锁。
  - 刷新阅读页后水合无报错。修了页面栈首屏沿用历史记录 `enter: 'dive'` 导致的不一致。

  - 深链接：试读开头直接换成正文，中间没有加载动画。
  - 竖排分页：点左侧是下一页，书脊在右侧；能跨章；窗口宽度正好是 9 列字宽。

## 4.3 用户追加：翻页模式与页眉页脚（2026-09-27，与 4.2 一起做）

要求见 [page-turn-modes](../memory/page-turn-modes.md)：六种模式（翻书、左右平移、上下平移、左右覆盖、上下覆盖、滚动）；五种分页模式里页眉页脚跟着书页动，滚动模式保持固定；新增"反向翻页"。

设计（实现中）：
1. 设置 `mode` 扩成 `flip | slide-x | slide-y | cover-x | cover-y | scroll`，新增 `reverse`；本地存储里的旧值（例如 `slide`）不做兼容，按非法值回落到默认的翻书。
2. 分页模式下每层页面是一整页：页眉（该页所在章的章名）+ 正文窗口 + 页脚（该页的全书进度与页码）。正文窗口的可用尺寸用一个隐藏的同结构"页框"量出来，因为页眉页脚的高度含安全区，只有 CSS 知道。
3. 统一用 `rtl = vertical !== reverse` 表示"下一页在左边"：决定点击区域、左右滑动与方向键的映射，翻书的书脊（rtl 时在右侧），左右平移、左右覆盖的方向。上下两种模式另外接受上下滑动（上滑 = 下一页）。
4. 覆盖：往后翻时上层（当前页）移开、下层（下一页）不动；往回翻时上一页从外面盖回来。移动的那页边缘带投影。
5. 设置面板：翻页方式用 3×2 卡片（带示意图），下面一行"反向翻页"开关。

**A. 背景面板（已完成，提交 7e02893）**

下面是动手前的设计，实际做法的差别写在列表后面。

实际做法与设计的差别：

## 4.7 用户追加：全书进度与"跳回"（2026-09-28，已完成，提交 381e11d）

**用户原话与已同意的方案**
- 用户问要不要在底栏加第四个入口"阅读进度"，放进度、阅读时间、笔记，并说"我的想法不一定正确"。我建议不加，用户回复"可以，我同意你的想法"。同意的方案是：

**这次做的（设计）**
- **全书进度条**：
  - 替换原来的本章页码滑块；分页、滚动两种模式都用它，本章页码仍在页脚。
  - 按章拖动。拖动时上方浮出将要去的那一章：章名、第几章 / 共几章、是否要订阅。松手才跳。
  - 跳完工具栏不收起，方便接着拖。
- **跳回**：
  - 什么算跳：进度条、目录、上一章、下一章。
  - 跳之前读到的位置记为"原位置"，按章与章内比例记，重新分页后仍能落回同一页。
  - 连跳几次，原位置仍是第一次跳之前那里。
  - 跳完后，页脚上方浮出一枚"回到第 N 章"，点一下回到原位置；工具栏唤出时它升到下栏上方。
  - 原位置在进度条上用一个空心小结标出。
- **什么时候消失**（用户纠正后的规则，见 [jump-back](../memory/jump-back.md)）：
  - 从落点往后净读满 3 页（滚动约 3 屏）。往回翻、往回滚要减掉，来回翻看不算。
  - 不按时间算。
  - 自己翻回或滚回原位置时，也会消失。
  - 起初的设计是"往后读 5 页并且读满 3 分钟"。用户在验收中途纠正："三分钟似乎太久了，并且读了六页还不消失也不合理，改成读一定进度后消失，避免用户切换章节后恰好长时间没空碰手机，同时通过向前读一定进度反而是真正证明用户要从这里开始看了"。
- **保存**：原位置按书存在本机，刷新或退出再进来仍在。
- **本次不做**：书签、笔记并进目录面板，以及阅读时间，都记进待办。

**验收（2026-09-28，Playwright，390×844 与 1440×900）**
- **进度条**：
  - 拖动途中地址不变，上方小笺显示"第二十六章 26 / 64"，未订阅的章带一把锁。
  - 松手跳到第二十六章，工具栏不收起。
  - 键盘每按一次方向键跳一章，焦点留在进度条上。
  - 竖排时整行镜像，进度从右往左。
- **跳回（分页）**：
  - 第一章 3/4 页拖到第二十六章后，小签升在下栏上方，写"回到第一章 靠窗的位置"；进度条起点出现空心小结。
  - 收起工具栏后，小签落到页脚上方。
  - 点小签回到第一章 3/4 页，本机记录清空。
  - 目录连跳第十章、第二十章，原位置仍是第一章。
  - 刷新后小签仍在；点它从尚未缓存的第一章按比例落回 3/4 页。

  - 连翻三页，在第三页消失。

## 4.8 用户追加：订阅页（2026-09-28，已完成，提交 65ec30e）

**用户原话**："优化：订阅增加预览开头部分，但是需要在服务器做安全限制，避免用户通过模拟请求超多内容（即避免利用bug绕过订阅以预览的身份获取全部内容）。订阅页可以做一些深入优化，增加一些功能比如订阅多章、自动订阅开关（注意只自动订阅本书，并且是随着阅读进度与缓存自动订阅（原设计就有自动提前加载后几章，相当于这里是自动订阅后几章），避免将自动订阅理解为直接订阅整本书），并深入思考还能怎么优化订阅界面，一定要优雅，以此可以略微增加一些读者的消费体验和消费意愿"

规则见 [subscription](../memory/subscription.md)。

**设计**
- **预览（服务端，packages/data/src/api.ts 模拟）**：
  - `chapterLead`：按段落顺序取到 200 字为止，同时不超过全章五分之一，最后一段在句末截断。没有任何参数。服务端渲染的试读开头也改用它。
  - 这一改修掉了一个现有的漏洞：原来试读开头是"前三段"，作者如果把整章写成两三段，HTML 里就是整章。
  - 预览接口 `fetchPreview` 模拟限频：每分钟 30 次，超出返回 limited，订阅页照常显示，只是没有预览。
  - 正式版在发布章节时就把开头截好、单独存一个字段，预览接口只读这个字段，根本不碰正文。
- **价格与余额（原型示例，货币名、价格与折扣待定）**：
  - 按字数计价，每千字 5 书币，字数暂按全书平均值上下浮动。
  - 本机模拟钱包，初始 600 书币；余额不足时"去充值"模拟充入 1000 书币。
- **订阅页**：
  - 上半部分是章名与预览，用正文的字体与排版，往下渐隐。竖排时预览也竖排，往左渐隐。
  - 下半部分是一张订阅笺，从上到下：
    - "订"字印章、"订阅后接着读"、本章字数、余额；
    - 订阅范围：本章 / 后 10 章 / 余下全部，各自写明章数与总价，默认选"本章"，不默认选多章；
    - 主按钮写明要花多少；
    - 自动订阅开关；
    - 一行小字："订阅后永久可读，也是对作者最好的支持"。
  - 订阅成功后原地淡入正文，并提示订了几章、余额还剩多少。
- **批量订阅（服务端检查）**：只收未订阅的章；余额不够就整笔不订；只返回最前面几章的正文，其余以后照常取。
- **自动订阅**：
  - 按书开关，放在订阅页和阅读设置里（开了以后就不会再看到订阅页，要有地方关）。
  - 只在读者往后读时触发，打开书、跳章都不触发（跳章不是阅读进度）。
  - 只订当前章之后 3 章以内的，与预取窗口一致；本次会话第一次自动订阅时提示一次。
  - 服务端拒绝：开关没开、正在读的那章本身不可读、超出窗口的请求。所以客户端出错也订不掉整本书。
  - 余额不够就停下，读到那章时显示订阅页。

实际做法与设计的差别：
- 预览按内容高度排，渐隐只盖最后约 6em。最初让预览撑满剩余高度，短预览的后半段先淡没了。
- 有跳回小签时，分页订阅页的订阅笺往上让出 54px。验收时发现小签压住了笺上的小字。
- 订阅笺算作控件，点它不会翻页。

**验收（2026-09-28，Playwright，390×844 与 1440×900）**
- **排版**：分页横排、分页竖排、滚动横排、滚动竖排四种都看过；长夜配色、宽屏也看过。
- **连订 10 章**：
  - 按钮写"订阅第 31–40 章 · 256 书币"，订阅中显示"请稍候"；
  - 成功后原地换成正文，提示"已订阅 10 章，余额 344 书币"；
  - 目录里第 31–40 章的锁去掉，第 41 章起仍有锁。
- **余额不足**：按钮写"余额不足，去充值（还差 258 书币）"；充值后余额 1344，按钮变回"订阅余下 24 章 · 602 书币"。

  - 开关按书存在本机。
  - 订完本章、还没往后读时，不自动订阅。
  - 往后翻一页，自动订阅第 42–44 章，只提示一次"已自动订阅 3 章，余额 1240 书币"。
  - 用目录跳到第 60 章不触发；在订阅页上往后翻，只提示"订阅本章后接着读"。
  - 阅读设置里的开关能打开、关闭。
- **服务端拒绝**（在页面里直接调用模拟接口）：越界、一次要二十章、自称在读一章没订阅的章、开关已关，四种请求都返回 refused，订阅记录不变。

- **服务端渲染**：第 31 章 HTML 里的试读开头是 6 段、177 字，末段截断，与预览一致。

## 4.9 用户追加：背景按配色做变体（2026-09-28 提出，2026-09-29 完成）

**用户原话**："背景可以继续深入优化，可以参考类似微信读书，对不同配色和背景纹理做特别适配，避免全部千篇一律，比如月影和星河明显值得在黑色背景下做深入优化变体，因为非常契合黑色背景。而比如树影在黑色背景下几乎不可见，显然是没有做好适配，而是只简简单单的分别做了配色和背景，然后简单的结合，没有想象力，且千篇一律，尤其是适配不好"
- 同日澄清："不是说每一个配色都要配不同背景变体，而是不能全部配色都配同一种背景设计，其中需要有一些不同（比如这几个配色搭配A种类，那几个配色搭配B种类，某个配色需要单独适配一个C种类才有合适效果），部分配色和背景直接还需要特别适配"

规则见 [reading-backgrounds](../memory/reading-backgrounds.md)。

**设计**：按配色分三组，只给树影、月色、星河换画法；其余纸张各组画法相同，只调颜色。
- **浅色六套**（薛涛笺、豆青、缃叶、天青、紫藤、盐汽水）：日影、淡月、星图。星图代替原来那道很淡的银河：浅色纸上画不出"亮"的夜空，就画成一页古星图。
- **墨白**：墨枝（同一枝画成水墨，分浓淡）、烘云托月（月亮不着墨，四周晕淡墨云）、星图。
- **长夜**：月下枝影（画月光，枝叶留成暗处）、夜月（更亮的月与月晕，纸色的云横过月面）、夜空（四档亮度的星，有星云团与暗尘带的银河）。
  另外把落英、猫爪、丝绢光泽调亮，原来的透明度在深色纸上几乎看不见。
- 画法写成颜色表里的变量，每套配色可以换；对比度脚本按实际用的画法定阈值。实现细节见 [实现说明](../docs/prototype.md) 第 10 节"背景"。

**过程中的问题**
- 用户第二次指出树影在黑色背景下还是看不清：那时变体图已经画好，但还没接进 papers.css，长夜仍在用旧的黑色影子。
- 夜月与烘云托月三张手写图一开始完全不显示：注释里写了 `--moon`，XML 注释不允许 `--`，浏览器解码失败，也不报错。生成脚本现在遇到会抛错。
- 月下枝影第一版在纸上留了一道斜的直边，枝影也歪了：遮罩挂在带 `rotate` 的椭圆上，跟着转了。改为挂在外层 `<g>` 上。
- 第一版银河只是两道椭圆加两条直的暗带，看起来像一道光束。改成沿芯排开的星云团，用噪声打散，暗尘带用噪声扭弯，两端淡出。

**验收（2026-09-29，Playwright，390×780）**

## 4.4 用户要求：点书翻面、书号（2026-09-27，已完成）

   实现要点：
   - `Book.id` 就是书号（字符串）。示例数据按 era 分配前缀：古代 1001、现代 1002、未来 1003，分类内按上架日期排序号。品牌书用预留号段。

  - 从页面 DOM 取出路径独立解码，得到 1002100000010006，校验正确，两侧静区各 10 个模块。
  - 书城 HTML 的 gzip 体积 34.5KB → 35.5KB。
