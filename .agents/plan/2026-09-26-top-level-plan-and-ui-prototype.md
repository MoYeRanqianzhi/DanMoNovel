**建议中，待用户确认**

## 4. 第二轮待办的规格与设计要点

用户原话要点，以及我已形成、**尚未实现也未验证**的设计思路。实现时以用户原话为准，思路可调整。

1. **书架显示格式**：保留现有两种，新增纯列表、更紧凑的列表等，各自命名。候选名称：陈列（现在的封面视图）、书柜（现在的书脊视图）、宫格（封面平铺）、书目（小封面加书名/作者/进度）、简目（纯文字紧凑列表）。切换入口改为带示意小图的选择面板，并记住选择。纯文字格式没有书位，点击后不走飞行过渡，详情页直接淡入。
2. **书脊方案落地**：`Book` 增加可选封面图片。自动生成的做法是：把封面画到小 canvas 上，左缘约 6% 的像素取平均作书脊底色；颜色量化后得到主色与点缀色；书脊字色在近黑与近白之间按 WCAG 对比度选。组件实验室里放一个"上传封面"演示，展示取色结果与转动后的书脊、封底。
3. **翻页模式**（名称可直接用行业惯例）：仿真翻页（现有 flip）、覆盖翻页（新页从一侧盖上来）、左右平移（现有 slide）、上下翻页（按页纵向移动）、连续滚动（现有 scroll）、无动画。6 个选项在设置面板里排成 3×2 的卡片，不用分段控件。
4. **菜单**：上栏放退出、小尺寸立体书、书名/作者/章节、书签开关、段评显示开关。下栏默认显示进度行（上一章 / 页码滑块 / 下一章）和一排入口：目录、文字、背景、翻页、夜间。点文字、背景、翻页时，面板在下栏上方展开：文字面板含字号、字体、行距、横排/竖排；背景面板含主题色样与亮度；翻页面板含模式卡片与读屏模式开关。目录做成抽屉，分目录、书签、笔记三页。
5. **段落与选择**：段评是段末的计数气泡，点开是评论面板（示例数据，发表需登录）。选择在触屏上是长按后拖动，鼠标是拖选，带选择手柄。工具条含复制、划线（红线波浪 / 淡粉荧光 / 墨线三种样式）、写想法、段评；点已有划线可以删除或查看想法。划线与想法按书和章节保存到 localStorage，并出现在笔记页。
6. **正文保护**（目标边界见记忆）：
   - Canvas 绘制正文：先用隐藏的测量容器（同样的多栏或竖排排版）逐字取 `Range.getBoundingClientRect` 得到每个字的位置与所在页，然后移除测量容器，把字画到每页的 canvas 上。测量前必须先 `document.fonts.load(字体描述, 本章文字)`，因为字体按需分片加载，而 canvas 不会在字体到达后自动重绘。横排用 alphabetic 基线，y 取字框顶加 `measureText().fontBoundingBoxAscent`；竖排在字框中心居中绘制，标点换成竖排专用字符（U+FE10–FE19、U+FE30–FE44）。设备像素比上限约为 3。滚动模式把各页竖向拼接（分块），避开 Safari 的 canvas 面积上限（约 1670 万像素）。选择、划线、段评气泡都基于逐字位置计算。
   - 加密传输：在前端做一个模拟服务端模块，用 WebCrypto 的 ECDH P-256 协商会话密钥（HKDF 派生），章节以 AES-GCM 加密下发，只在内存中解密。
   - 内置复制：未登录时弹出登录面板（示例账号）；服务端校验单次字数上限、每日配额与频率，返回正文并附出处（可选附加零宽字符指纹，便于追溯）。剪贴板写入：Chrome 在 await 之后调用 `navigator.clipboard.writeText` 可用；Safari 要在手势内同步创建 `ClipboardItem` 并传入 Promise；Tauri 用剪贴板插件。拦截系统的复制、右键菜单与打印。
   - 读屏模式：改为渲染 DOM 文本，作为无障碍兜底；为 AI 听书预留一条同样走鉴权与限速的正文获取通道。
7. **docs/**：见待办。架构文档要写明旧方案的教训：避免为跨端共享 UI 而自建适配层与预览版依赖。

## 4.1 第三轮待办的规格与设计要点

需求原话与判断理由见各条记忆；这里只记实现层面的思路，**尚未实现也未验证**。

1. **三站结构**（取决于 Web 框架：用户 2026-09-27 指出框架一直没定下，商业站需要能做缓存与搜索优化的框架，见 [web-framework](../memory/web-framework.md)。框架定下之前只做与框架无关的工作；定下后很可能改为 pnpm workspace 的 `apps/`（各站）加 `packages/`（共享设计系统）结构，下面这套 Vite 多入口方案作废）：`prototype/src/` 拆成 `shared/`（令牌与主题样式、theme、book3d、flight、基础组件、lib、data、fonts）与 `novel/`、`author/`、`admin/` 三个站点目录。每个站一个 HTML 入口 `prototype/sites/<站点>/index.html`。一个启动脚本用 Vite 的 JS 接口在同一进程里起三个开发服务器：5173 小说站、5174 作者站、5175 管理站。`vite build` 按站点分别输出到 `dist/<站点>/`。
2. **字体**（共享模块 `shared/fonts/`）：平台字体目录（名称、分类、许可、客户端下载大小、网页字体入口）；按需动态加载网页字体 CSS；"系统字体"只是一个用 `system-ui, sans-serif` 的选项（用户纠正，不检测也不枚举）；导入字体（校验文件头，解析 name 表取字体名，存 IndexedDB，FontFace 注册）。原型通过"模拟客户端"开关展示下载按钮与进度，下载本身是模拟的。阅读器"文字"面板里的字体行点开后是一页可滚动的字体列表，预览当前段落的文字。
3. **作者站**：书房首页（今日字数、连更印章、在写的书、审核与编辑消息）、作品（列表与作品设置，封面上传后自动生成书脊与封底，并用 3D 书转动展示）、章节与写作编辑器（电脑端三栏：章节列表、正文、信息与预览；手机端单栏切换）、数据（红线折线图）、读者互动。
4. **管理站**：总览、审核队列与审核详情、作者（编辑视角）、身份（层级图：红线表示"谁能任命谁"，身份用印章样式的标签表示）、审计日志、站点设置。提供原型专用的"以某个身份预览"切换，按 staff-roles 的规则显示或禁用操作。功能不接数据，按钮给出"原型阶段未接入"的提示。
5. **电脑端布局**：逐页在 1440×900 等宽视口下设计与验收。阅读器在宽屏下默认对开两页，仿真翻页以中缝为轴；详情页左书右信息；书架多列；面板在宽屏改为贴近工具栏的浮层而不是底部抽屉。
