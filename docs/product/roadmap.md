# 路线图

版本号的格式是 `x.x.x-alpha.x`、`x.x.x-beta.x`、`x.x.x-rc.x`，正式版去掉后缀。

## 0.1.0-alpha.1：三站 UI 原型（已完成）

界面完整、数据是示例、没有接后端。目的是先把界面与体验定下来，审查通过之后再做真实功能。

- **共享的设计系统**：八套主题与设计令牌、3D 书本 Book3D、书在页面之间的飞行过渡、页面栈、印章与盖章、底部面板、选项卡片、稿纸、远山图。
- **小说站**：书城、书架（四种摆法）、发现、我的、书的详情页；阅读器的六种翻页方式、横排与竖排、宽屏对开、十种纸张按配色分组的画法、阅读字体（平台字体、系统字体、导入字体）、书签、划线、想法、段评、全书进度与跳回、阅读时间、订阅页。
- **作者站**：公开首页（作者招募）、书房、作品与封面工作室、方格稿纸的写作页（发布与送审、退回的朱批）、互动、数据、我。
- **管理站**：总览、审核（朱批与盖章）、身份（以某个身份预览）、审计日志、作者、设置。
- 每个页面都分别设计了手机与电脑的布局，在浏览器里看过手机、横放手机、竖放平板、桌面几种视口与深色主题。

## 接下来

下面按大致的先后排列。每一步的范围与做法，开工前还会细化。

1. **原型审查**：项目方审查三站的界面与体验，提出修改意见。审查通过之前不开始后端。
2. **框架验证**：同一套小说站代码同时产出服务端渲染构建与客户端用的 SPA 构建；`isbot` 能否认出国内搜索引擎的爬虫；一个 Node 进程同时跑小说站与作者站两份服务端构建。见 [技术架构](../architecture/overview.md#8-还要验证的几件事)。
3. **后端**：Go 服务（三个端口、转发服务端渲染、提供管理站静态包）；账号与三站各自的会话；书、章节、书号；章节预览与订阅；评论与段评；身份、权限与审计日志；PostgreSQL 与 Redis。
4. **前端接入真实接口**：`packages/data` 从示例数据换成调用后端接口的客户端；本机保存的书签、划线、偏好改为与账号同步。
5. **正文保护**：Canvas 绘制正文、加密传输、内置复制、读屏模式，以及给 AI 听书预留的受控正文通道。见 [阅读器与内容保护](../design/reader.md#9-正文保护)。
6. **客户端**：Tauri 2 的桌面与手机客户端（字体下载、剪贴板、文件导入）；之后是鸿蒙（ArkWeb）。
7. **部署**：Docker Compose，一条命令完成首次部署与之后的升级。
8. **更广的验收**：真机上的输入法与软键盘、横放手机的刘海、Safari 与 Firefox、读屏软件的实际朗读。
