# Book3D 规范

耽墨的每一本书，在每个页面上都是同一个 3D 书本组件 Book3D（`packages/design/src/book3d/`）。书城、书架、详情、阅读器、作者的书房、管理站的审核台，用的都是它。它是设计语言里“书是主角”这一条的载体（见 [设计语言](design-language.md)）。

## 1. 为什么用 CSS 3D

书是由真实的 DOM 元素搭起来的立体盒子，不是 WebGL 画布。理由：

- 书上的书名、作者、简介都是真的文字，可以被选中、被读屏念出，也随主题变色；
- 同一本书可以在两个页面之间飞行、在飞行途中转身和开合，不需要在两个渲染系统之间交接；
- 浏览器、WebView2、WKWebView、Android WebView 都支持，客户端用同一套代码。

动画不用动画库：书的姿态由几个用 `@property` 注册过类型的 CSS 变量描述，CSS 动画和 Web Animations API 直接对它们插值。

## 2. 书的构造

一本书由这些面组成：封面（外侧与内侧，内侧是一张藏书票）、书脊、封底、上下与外侧三条书口、书芯、若干张能单独翻动的内页，以及一条书签丝带。投影放在 3D 树之外，所以抬起、放下时投影可以单独变化。

坐标约定：x 向右，y 向下，z 朝向观察者。封面在书的前面，书脊在左边。

光照按书的朝向计算：书转过来时，各个面的明暗和封面的高光位置跟着变，不需要真的光源。

## 3. 尺寸与比例

- 书的比例固定为 200×284（约 1:1.42），接近常见的小说开本。
- 书的宽度由使用的地方给出，可以是一个数，也可以是“窄屏一个、宽屏一个”（900px 以上用宽屏的那个）。
- **厚度随字数变**：厚度与宽度之比从 0.07 起，每一百万字加 0.12，最厚 0.26。读者一眼就看得出一本书是短篇还是长篇。
- 封面、书脊、封底上的平面内容都按 200×284 的基准排版，再整体缩放到实际大小。所以一套排版在大书小书上都一样好看；也因为这样，基准下的字号不能小于 12px。

## 4. 姿态与状态

### 4.1 姿态预设

| 姿态 | 俯仰 / 转身 | 用在哪里 |
|---|---|---|
| `hero` | −8° / 26° | 展示：露出封面与书脊，最像一本立体的书。书城的主角、书架的“继续读” |
| `shelf` | −5° / 18° | 轻微转身，露出一点厚度。书架的“陈列”、读完的书 |
| `thumb` | −2° / 12° | 几乎正对封面，只露一丝书脊。列表、榜单里的小书 |
| `front` | 0° / 0° | 正面。书架的“宫格” |
| `spine` | −4° / 88° | 书脊正对观察者。只用于书架的“书柜”格式 |

### 4.2 状态

- **静止**：放在那里。
- **漂浮**：缓缓起伏，6.4 秒一个来回。一屏最多一本，只给主角书。
- **加载**：书仰躺，封面打开，内页一张接一张地翻，2.6 秒一个循环。它是加载动画，只在内容确实还没到时出现（等待超过一个很短的阈值才显示）。

### 4.3 交互

- **悬停倾斜**：只在鼠标这类精确指针下启用，书朝指针微微转过来。
- **点一下翻面**：点一下书，转到另一面（封面 ↔ 封底）；转到一半再点，也不会掉头。键盘用回车或空格。
- **拖动转着看**：横向拖动超过 6px 才开始跟手转，松手后按惯性吸附到正面或背面。没开始拖、按住不到半秒就松手，算“点一下”。
- 这些动画都按经过的时间推进，在 60Hz 和 165Hz 的屏幕上一样快。

### 4.4 实现上的禁忌

承载 3D 的那几层（`.book3d__float`、`__body`、`__cover`、`__leaf`）不能加 `overflow`、`opacity`、`filter`、`clip-path`、`mask`，否则会被浏览器压扁成平面。书的根元素不让选中文字，否则拖书会先选中书上的字，接着变成浏览器的原生拖拽。

## 5. 三个面：封面、书脊、封底

封面、书脊、封底三个面**各自**可以“合成”或“上传图片”，互不绑定。新书默认三面都合成。

### 5.1 合成

平台用矢量画出来的封面。作者在作者站的封面工作室里可以改：

- 装帧：**线装**（左侧钉线、右上题签、左下一方闲章）或**现代**（右侧竖排书名、下方一条腰封）；
- 配色、纹样（10 种，另有“无”）、书名字体（6 种）、横排或竖排、腰封与文案、点缀（5 种）。

合成的书脊与封底跟着封面的颜色，天然成套。封面换成了上传的图片，书脊和封底也照样可以合成：书脊取封面最左一列的颜色或主色，封底用主色，或者把封面翻转、虚化后延续过去。书脊有五种样式，封底有三种。

纹样的随机分布以书号为种子，同一本书在服务端和浏览器里、在每次打开时都长得一样。纹样会避开书名和腰封的位置。

### 5.2 上传图片

上传的图一律经过裁剪器，比例固定，导出固定像素的 PNG：

| 面 | 像素 |
|---|---|
| 封面 | 800×1136 |
| 书脊 | 208×1136 |
| 封底 | 800×1136 |

- 尺寸固定，是为了让每本书的模板都一样，也避免各种尺寸带来的问题。
- 书脊按最厚的书定宽，薄书只露出中间一段。书脊上的字要放在正中 56px 宽的安全区里。
- 耽墨的标记烤进图里：封面是朱印加“耽墨文库”，书脊是朱印，封底是书号条码加朱印。作者可以在裁剪器里拖动、缩放标记，但大小有下限，封底的条码缩到最小仍然扫得出来。

> 早期曾计划让作者按模板上传封面、书脊、封底连在一起的整张包封图，尺寸按字数推算。2026-09-29 改成三个面分别上传、尺寸固定，那个方案已作废。

### 5.3 展示规则

书脊在小尺寸下看不清书名。所以列表、榜单、书城等地方一律**封面朝外**（`thumb`、`shelf`、`hero`）。书脊朝外的 `spine` 只用在模拟实体书架的“书柜”格式里；3D 转动和飞行途中自然露出的书脊不算。

## 6. 书号与封底条码

- **书号**是一本书唯一的索引：16 位十进制数字，以 1 开头，只分配一次，永不改变。书号本身不含任何信息，不能从书号推断分类或其他属性；要知道分类就查数据。书名、简介、分类、章节都可以改，只要书号一样，就还是同一本书。
- 展示时写作 **DMBN**（仿照 ISBN）加四位一组的书号，例如 `DMBN 1001 1000 0001 0001`。
- 16 位数超出 JavaScript 能精确表示的整数范围，所以前端、JSON、本机存储里书号一律是字符串。地址、接口、数据库、缓存都用书号标识书，不用书名或拼音。
- **封底条码**编码完整的 16 位书号。EAN-13 只装得下 12 位，所以用 Code 128C。条码下方印 DMBN 与书号，整块只占封底宽度的四分之一左右。

## 7. 飞行过渡

同一本书在页面之间飞，是耽墨页面衔接的核心（`packages/design/src/flight/`）。

- 页面上每个“书位”都登记一个名字。跳转时，起点和终点的书位都登记好了，才开始测量和起飞：两端的书先藏起来，一本替身书在最上层沿曲线飞过去，到了再换回终点的真书，中间不留空帧。
- 三种飞行：
  - **hop**：书位到书位，760ms，沿一条微微上抬的弧线，途中轻轻歪一下；
  - **dive**：开书推进，1500ms。书移到屏幕中间、打开、右手页放大到铺满屏幕，正文就在这一页上出现；
  - **surface**：从阅读器回去，1300ms，dive 倒过来。
- 页面是一个“栈”：新页面盖在旧页面上淡入，旧页面不卸载；返回时顶层淡出，露出原封不动的上一页，书飞回原来的位置。
- 不用浏览器的 View Transition API：它补间的是平面快照，书在途中不能真正地转身与开合。
- 减少动效时，书不起飞，页面直接切换。
